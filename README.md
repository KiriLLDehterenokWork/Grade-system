# Информационная система учёта оценок студентов (Student Grade System)

Монолитное веб-приложение для автоматизации учёта академической успеваемости студентов с ролевым разграничением доступа (RBAC), серверным рендерингом страниц и контейнеризацией.

## Технологический стек

* **Java 21**
* **Spring Boot 3.3.5** (Spring Web, Spring Data JPA, Spring Security, Validation)
* **Базы данных:** PostgreSQL (основная БД), H2 Database (in-memory БД для тестирования)
* **Миграции БД:** Flyway
* **Фронтенд:** Thymeleaf, Bootstrap 5, кастомные CSS-стили
* **Тестирование:** JUnit 5, Mockito, MockMvc, Spring Security Test
* **Контейнеризация и сборка:** Docker, Docker Compose, Maven

---

## Ролевая модель и функционал

Доступ к разделам системы разграничен с помощью **Spring Security**:

1. **Администратор (`ADMIN`)**
    * Создание и просмотр учебных групп и дисциплин (предметов).
    * Регистрация преподавателей с привязкой к закрепленным за ними предметам.
    * Регистрация студентов с распределением по учебным группам.
    * Удаление учетных записей пользователей.

2. **Преподаватель (`TEACHER`)**
    * Выставление оценок (по 10-балльной шкале с выбором даты) студентам по закрепленным за преподавателем предметам.
    * Редактирование ранее выставленных оценок и дат.
    * Удаление оценок из журнала.

3. **Студент (`STUDENT`)**
    * Просмотр истории своих оценок с датами, предметами и ФИО преподавателей.
    * Автоматический расчет среднего балла отдельно по каждому предмету.
    * Автоматический расчет общего среднего балла (с округлением до сотых).

## Архитектура и обработка ошибок

Проект построен по классической многослойной архитектуре:
* `entity` — сущности БД (`User`, `StudyGroup`, `Subject`, `Grade`, `Role`).
* `repository` — репозитории Spring Data JPA с оптимизированными `JOIN FETCH` запросами.
* `service` — бизнес-логика и транзакционные методы (`AdminService`, `GradeService`).
* `controller` — MVC-контроллеры ролей и глобальные обработчики ошибок.
* `config` — конфигурация безопасности (`SecurityConfig`), `CustomUserDetailsService` и автозаполнение начальных данных (`DataInitializer`).

Реализована кастомная обработка ошибок:
* **Ошибка 404:** перехватывается через `CustomErrorController` и возвращает страницу `error-404.html`.
* **Ошибка 500:** перехватывается глобальным обработчиком `@ControllerAdvice` (`GlobalExceptionHandler`) и отображает `error-500.html` (тестовый вызов доступен по маршруту `/checkError`).

## Инструкция по запуску

### Способ 1. Полный запуск в Docker (рекомендуемый)

Для запуска не требуется установленная Java или локальная СУБД — достаточно **Docker Desktop**.

1. Откройте терминал в корневой папке проекта и выполните команду:
   ```bash
   docker compose up --build -d
   ```
2. Откройте браузер и перейдите по адресу:
   ```text
   http://localhost:8080
   ```
3. Для остановки всех контейнеров выполните команду в консоли:
   ```bash
   docker compose down
   ```

---

### Способ 2. Локальный запуск через IDE (для разработки)

1. Запустите базу данных PostgreSQL в Docker командой:
   ```bash
   docker compose up postgres -d
   ```
2. Откройте проект в IntelliJ IDEA и запустите класс `GradeSystemApplication`.

## Запуск автотестов

Модульные (JUnit 5 + Mockito) и интеграционные (MockMvc) тесты выполняются на изолированной in-memory базе данных **H2** (профиль `test`) и не требуют запущенного Docker-контейнера:

```bash
mvn test
```
